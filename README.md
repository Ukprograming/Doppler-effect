# ドップラー振動数ラボ

高校物理のドップラー効果の定量実験で使う、ブラウザベースの振動数測定アプリです。斜面を下る台車に固定したスマートフォンから純音を出し、斜面下側のPCマイクで観測振動数の時間変化を測ります。

PCが直接測る量は観測振動数 `f` です。アプリは最初に `f-t` グラフを表示し、生徒の操作後に `Δf = f - f₀` へ切り替えます。音源速度 `v` は計算しません。生徒はCSVをGoogleスプレッドシートへ読み込み、ドップラー効果の式を使って速度を求めます。

## 主な機能

- マイク入力デバイスの選択と、実際に適用された音声処理設定の確認
- 静止時の基準振動数 `f₀` のロバストな測定
- 台車運動中のモノラルPCM音声の記録
- Web Worker内のSTFT、FFT、ピーク補間による `f(t)` 推定
- 測定品質の判定と、低品質点を残したままの可視化
- 解析範囲と「台車を離した瞬間」`t = 0` の指定
- `f-t` と `Δf-t` の教育的な段階表示
- CSV、WAV、グラフPNG、測定条件JSONの保存
- 保存済みWAVの読み込みと、設定を変えた再解析
- マイクなしで操作を試せるチャープ音のデモデータ

音声や測定データをサーバーへ送信する処理はありません。すべてブラウザ内で処理します。

## 実験の概要

1. スマートフォンを力学台車へ固定し、一定振動数の純音を出します。
2. 台車を静止させた状態で、PCマイクを使って基準振動数 `f₀` を測ります。
3. 台車を斜面上から離し、PCへ近づく間の音声を記録します。
4. 測定範囲と、台車を離した瞬間 `t = 0` を指定します。
5. `f-t` グラフでPCが観測した量を確認します。
6. 「基準の振動数からの『ずれ』を見る」を押し、`Δf = f - f₀` を確認します。
7. CSVをGoogleスプレッドシートへ読み込み、物理モデルから速度を求めます。

## マイク権限とHTTPS

ブラウザの `getUserMedia()` は、安全なコンテキストでのみ使えます。

- GitHub PagesなどのHTTPS URLでは利用できます。
- ローカル開発では `http://localhost` が例外として利用できます。
- LAN内のIPアドレスをHTTPで直接開いた場合、マイクを利用できないことがあります。
- 権限を拒否した場合は、アドレスバー付近のサイト設定からマイクを許可してください。
- 他のアプリがマイクを使用していると、開始に失敗する場合があります。

アプリは可能な範囲で次を無効にしてマイクを要求します。

```text
echoCancellation: false
noiseSuppression: false
autoGainControl: false
```

ブラウザやマイクドライバが要求を無視することがあるため、ステップ1に実際の適用値を表示します。

## 基本的な操作

### 1. マイクの準備

「マイクの使用を許可」を押し、入力デバイスを選びます。音量表示が「測定できる音量です」になるように音源の向きと距離を調整します。「音量が小さめです」または「音が大きすぎます」と表示された場合は、音源の音量または距離を調整します。

### 2. 基準振動数

台車を静止させ、純音を鳴らしたまま「基準振動数を測定」を押します。3秒のカウントダウン後、初期設定では1.8秒を記録します。結果と品質を確認し、「この値を基準にする」を押します。

### 3. 本測定

「測定開始」を押します。カウントダウン後に台車を離し、必要な区間まで記録したら「測定を停止」を押します。初期設定では10秒で自動停止します。

### 4. 範囲と時刻原点

3本のスライダーで、解析開始、台車を離した瞬間、解析終了を指定します。CSVの `time_s` は台車を離した瞬間が0秒です。

### 5. グラフと出力

最初に `f-t` グラフを確認します。「基準の振動数からの『ずれ』を見る」を押すと、`Δf = f - f₀` の関係を表示して `Δf-t` へ切り替わります。グラフ上の点を選ぶと、振動数、品質、解析窓を確認できます。

## 周波数解析

### 音声取得

`getUserMedia()`でマイクストリームを取得し、`AudioContext`の実際のサンプリング周波数を使います。`AudioWorklet`でモノラルPCMを取り出し、記録終了後にWeb Workerへ渡します。音量の簡易表示には`AnalyserNode`を使いますが、振動数の測定値はPCMから生成します。

### STFTとFFT

各解析窓で次を行います。

1. 平均値を引き、DC成分を除去
2. Hann窓を適用
3. 次の2のべき乗までゼロパディング
4. Radix-2 FFTを実行
5. `f₀ ± 探索範囲`だけを探索
6. 最大パワーのビンを選択
7. 最大ビンと左右のビンの対数パワーを使って放物線補間
8. 信号レベル、ピークの突出、明瞭さ、クリッピングから測定品質を計算
9. 3点中央値フィルタで軽く平滑化

基準振動数 `f₀` は、複数の有効な解析窓から得た生の推定値の中央値です。

## 解析時間幅と周波数分解能

初期設定の解析時間幅は0.20秒です。このとき `1 / T = 5 Hz` が基本的な周波数間隔に関係します。

- 短い窓は時間変化を追いやすい一方、振動数推定が不安定になりやすくなります。
- 長い窓は振動数推定が安定する一方、急な時間変化を平均化しやすくなります。

FFTビン間隔、ピーク補間後の推定値、実際の測定精度は同じではありません。ゼロパディングはFFTの周波数格子を細かくしますが、短い観測時間が持つ本質的な分解能を改善しません。画面で0.1 Hzまで表示しても、0.1 Hzの測定精度を意味しません。

## 測定品質

測定品質は厳密な確率や不確かさではなく、測定点を判断するための指標です。

- 信号のRMSレベル
- 探索範囲内のピークと背景ノイズの比
- 主ピークと他のピークの分離
- クリッピングの割合
- 探索範囲の端にピークが張り付いていないか

品質は「良好」「注意」「測定困難」で表示します。色だけでなく文字、丸・三角などの形も使います。低品質点は削除せず、CSVとグラフに残します。

| 項目 | 初期値 |
| --- | ---: |
| 想定音源振動数 | 4000 Hz |
| 基準音の測定時間 | 1.8 s |
| 本測定の最大時間 | 10 s |
| 解析時間幅 | 0.20 s |
| 更新間隔 | 0.05 s |
| 探索範囲 | `f₀ ± 100 Hz` |
| 窓関数 | Hann |
| ピーク補間 | 使用 |
| 平滑化 | 3点中央値 |

## CSV列

| 列 | 内容 |
| --- | --- |
| `time_s` | 指定した `t = 0` からの代表時刻 |
| `frequency_hz` | 平滑化後の観測振動数 |
| `delta_f_hz` | `frequency_hz - baseline_frequency_hz` |
| `frequency_raw_hz` | 平滑化前の推定値 |
| `quality` | 0から1の測定品質スコア |
| `valid` | 品質基準を満たすか |
| `window_start_s` | 解析窓の開始時刻 |
| `window_end_s` | 解析窓の終了時刻 |
| `baseline_frequency_hz` | 静止時の基準振動数 `f₀` |

CSVはUTF-8 BOM付きで、GoogleスプレッドシートやExcelへ読み込みやすい形式です。数値は機械処理用に小数6桁で保存します。画面表示は原則として小数第1位です。速度の列は作りません。

## 既知の制約

- マイクの周波数特性、内蔵処理、設置方向によって品質が変わります。
- 一部のブラウザやドライバは、無効化を要求した自動音声処理を適用する場合があります。
- スマートフォンの純音出力周波数にも機器依存のずれがあります。
- 周囲の反射音、他の高周波音、台車の振動音はピーク推定へ影響します。
- WAV読込はPCM 16/24/32bitまたはFloat 32bitに対応します。圧縮形式をWAVコンテナへ入れたファイルには対応しません。
- グラフPNGはブラウザのSVG描画機能を使うため、フォントの見え方が環境により少し異なります。
- Chromebookや低性能PCでは、長時間記録と細かい更新間隔の組み合わせで解析時間が長くなる場合があります。

## PCマイクとブラウザによる違い

- 内蔵マイクは会話帯域へ最適化され、4000 Hz付近を弱く記録することがあります。
- 外部マイクを使う場合は、入力デバイス選択後にマイクを選び直してください。
- ChromeとEdgeで実際の`AudioContext.sampleRate`が異なる場合があります。アプリは固定せず実測値を使用します。
- OSの「音声の拡張」「ノイズ抑制」「自動音量調整」が有効な場合、ブラウザ設定より優先されることがあります。

## 実験前の動作確認

1. 実際に使うPC、ブラウザ、マイクを準備します。
2. 授業で使うスマートフォンから4000 Hzの純音を出します。
3. ステップ1で音量が小さすぎず、クリッピングしていないことを確認します。
4. 台車を静止させて基準音を3回測り、`f₀`が大きく変わらないことを確認します。
5. 台車を手でゆっくりマイクへ近づけ、`f-t`が増加することを確認します。
6. CSVをGoogleスプレッドシートへ読み込み、列が分かれて表示されることを確認します。
7. 本番と同じHTTPS URLまたはlocalhostでマイク権限を確認します。
